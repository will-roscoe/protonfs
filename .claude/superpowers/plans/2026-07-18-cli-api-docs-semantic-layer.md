# CLI/API Documentation Semantic Layer — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the docs a semantic, cross-referenceable layer for the CLI and Python API — sphinx-click autodoc for commands, native `confval`/`envvar` for config/env, roles wired through the narrative, plus autosummary / inheritance diagrams / a doc-coverage gate.

**Architecture:** Hybrid — sphinx-click autogenerates the mechanical command surface from the live Click app (single source of truth, cross-ref targets); a hand-authored config page owns `confval`/`envvar` targets; the existing behavioral prose stays and links into those targets via roles. Enforcement comes from a `-W --keep-going` build in CI.

**Tech Stack:** Sphinx 9.1, furo, sphinx-click, sphinx.ext.{autosummary,coverage,inheritance_diagram}, Graphviz, Click.

## Global Constraints

- No `src/` behavior changes — docs-only (`docs/`, `docs/conf.py`, `pyproject.toml [docs]`, `.github/workflows/docs.yml`).
- Preserve the frozen public contract; docs describe it, never alter option/config/env names.
- Commit style: conventional commits, exactly ONE trailer `Helped-By: claude-opus-4-8 <anthropic@willroscoe.uk>`.
- Config keys (verbatim): top-level `remote_root` (env `PROTONFS_REMOTE_ROOT`), `device_id` (env `PROTONFS_DEVICE_ID`); `defaults.on_conflict` = `"skip"` (env `PROTONFS_ON_CONFLICT`), `defaults.low_io` = `false` (env `PROTONFS_LOW_IO`), `defaults.event_log` = `false` (env `PROTONFS_EVENT_LOG`), `defaults.progress_style` = `"inline"` (env `PROTONFS_PROGRESS_STYLE`). Path override env: `PROTONFS_CONFIG`.
- CLI entry: `protonfs.cli:main` (a `click.group(cls=PositionalFlagGroup)`), prog name `protonfs`.
- Local build command used as the "test" throughout: `sphinx-build --keep-going -b html docs/ docs/_build/html`. Add `-W` where a task says "strict".

```rst
Configuration & environment (reference)
=======================================

Canonical definitions for every config key and environment variable. The
:doc:`../stability` page states which of these are frozen; this page defines them.
Keys are set with ``protonfs config set <key> <value>`` and read from the layered
config (env var > per-repo local > global user file).

Config keys
-----------

.. confval:: remote_root
   :type: str

   Proton Drive path that maps to this repo's ProtonFS root. Overridable via
   :envvar:`PROTONFS_REMOTE_ROOT`.

.. confval:: device_id
   :type: str

   Stable identifier for this client device in the index. Overridable via
   :envvar:`PROTONFS_DEVICE_ID`.

.. confval:: defaults.on_conflict
   :type: str
   :default: "skip"

   Action when a file is in :class:`~protonfs.diff.SyncState` conflict. Overridable
   via :envvar:`PROTONFS_ON_CONFLICT`.

.. confval:: defaults.low_io
   :type: bool
   :default: false

   Skip hashing unchanged files. Overridable via :envvar:`PROTONFS_LOW_IO`.

.. confval:: defaults.event_log
   :type: bool
   :default: false

   Enable the structured rotating event log. Overridable via :envvar:`PROTONFS_EVENT_LOG`.

.. confval:: defaults.progress_style
   :type: str
   :default: "inline"

   Progress display style, ``inline`` or ``lines``. Overridable via
   :envvar:`PROTONFS_PROGRESS_STYLE`.

Environment variables
---------------------

.. envvar:: PROTONFS_CONFIG

   Overrides the global config file path outright.

.. envvar:: PROTONFS_REMOTE_ROOT

   Per-key override for :confval:`remote_root`.

.. envvar:: PROTONFS_DEVICE_ID

   Per-key override for :confval:`device_id`.

.. envvar:: PROTONFS_ON_CONFLICT

   Per-key override for :confval:`defaults.on_conflict`.

.. envvar:: PROTONFS_LOW_IO

   Per-key override for :confval:`defaults.low_io`.

.. envvar:: PROTONFS_EVENT_LOG

   Per-key override for :confval:`defaults.event_log`.

.. envvar:: PROTONFS_PROGRESS_STYLE

   Per-key override for :confval:`defaults.progress_style`.
```

- [ ] **Step 2: Replace bare spans with roles (the change)**

Convert, in prose only (leave code-block examples as literal shell):
- `` ``protonfs push`` `` (as a reference, not inside a `.. code-block::`) → `:program:`protonfs push``
