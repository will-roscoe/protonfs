# Spec A — CLI/API Documentation Semantic Layer

Date: 2026-07-18
Status: approved (design)
Scope: `docs/`, `docs/conf.py`, docs dependencies, docs CI. No `src/` behavior changes.

## Problem

The command reference (`docs/reference/index.rst`) is entirely hand-written prose +
`list-table`s. There are **no semantic directives and no cross-reference targets** for
flags, subcommands, config keys, or env vars (`grep` confirms zero usage of
`option::`/`confval::`/`envvar::`/`program::`/`versionadded` across `docs/` and `src/`).
Consequently a specific flag/option/config key cannot be referenced the way a Python
function can (`:func:`), which is clunky and drift-prone.

The CLI is a **Click** app with a single entry point `protonfs.cli:main` (a
`click.group` using a custom `PositionalFlagGroup`). Build stack: Sphinx **9.1**, furo,
autodoc/napoleon/typehints/copybutton/tippy/intersphinx.

## Decision

Adopt an autodoc-plus-narrative ("hybrid") architecture:

- **sphinx-click** autogenerates the canonical mechanical surface (synopsis, options,
  args, envvars) per subcommand from the live Click objects — single source of truth,
  always in sync, emits cross-referenceable `.. program::`/`.. option::` targets.
- Native **`.. confval::`** (Sphinx 8.1+, so available on 9.1) and **`.. envvar::`**
  document config keys and env vars with first-class cross-ref targets — no extension.
- The curated **behavioral narrative + worked examples stay**, rewired to link into the
  autogenerated targets via `:option:`/`:confval:`/`:envvar:`/`:program:` roles.

Sequencing: this is **Spec A**. The `versionadded`/`versionchanged`/`deprecated` audit
is a separate **Spec B** done afterward (the commands page will host those notes later).

## Components (isolated units)

1. **`docs/conf.py` — extensions block.** Add `sphinx_click`, `sphinx.ext.autosummary`,
   `sphinx.ext.coverage`, `sphinx.ext.inheritance_diagram`. Keep existing `-W`/nitpicky
   posture so unresolved cross-references fail the build.

2. **`docs/reference/commands.rst` (new) — command autodoc.**
   ```rst
   .. click:: protonfs.cli:main
      :prog: protonfs
      :nested: full
   ```
   Recurses every subcommand into its own section. Global options render on the root
   group. This page owns the `:program:`/`:option:` targets.

3. **`docs/reference/config.rst` (new) — config/env reference.** Hand-authored
   `.. confval::` per `defaults.*` key (`:type:`, `:default:`, env-var link) and
   `.. envvar::` per `PROTONFS_*`, sourced from the `Defaults` dataclass / `KNOWN_KEYS`.
   Owns the `:confval:`/`:envvar:` targets. Accepted as manual-sync (small, frozen surface).

4. **`docs/reference/index.rst` (edit) — narrative rewire.** Keep prose + examples;
   replace bare code spans with real roles (`:option:`protonfs push --dry-run``,
   `:confval:`defaults.event_log``, `:envvar:`PROTONFS_EVENT_LOG``, `:program:`protonfs push``).

5. **`docs/stability.rst` (edit) — contract page.** Keeps the guarantee; links to the
   `config.rst` `confval`/`envvar` definitions instead of restating them.

6. **`docs/api/*` (edit) — Python API side.** `autosummary` overview tables;
   `inheritance_diagram` on the real hierarchies (the `click.Group` subclasses in
   `cli.py`, the exception tree); these render the module→class→method structure.

7. **CI / build.** Add Graphviz to the docs workflow (needed by `inheritance_diagram`);
   add a `sphinx-build -b coverage` gate (complements the interrogate badge); add
   `sphinx-click` to docs requirements.

## Cross-reference conventions

- CLI: `:program:`protonfs push`` / `:option:`protonfs push --dry-run``
- Config: `:confval:`defaults.event_log``
- Env: `:envvar:`PROTONFS_EVENT_LOG``
- Existing Python: `:func:` / `:class:` / `:mod:` unchanged.

## Risks & mitigations

- **sphinx-click vs `PositionalFlagGroup` + `_EpilogGroup`.** Custom `parse_args`/epilog
  machinery could confuse the autodoc. **Plan step 0 is a spike**: build `commands.rst`
  against the real app and confirm output. Fallback: hand-author `.. program::`/`.. option::`.
- **`inheritance_diagram` needs Graphviz.** Add to CI; document local requirement; the
  build fails loudly if absent (acceptable, not silent).
- **Native `confval` on 9.1.** Expected present (8.1+); verify in the spike. Fallback: a
  minimal custom directive or `.. option::`.
- **Dangling cross-refs.** Become build warnings; the `-W` posture turns them into hard
  failures, which is the enforcement we want.

## Out of scope (YAGNI)

`sphinx-needs`, `sphinxnotes-any`, `sphinx-dynamic-command-builder`, and the niche
`sphinx-gp-*` / `sphinx-ux-badges` / `sphinx-ux-autodoc-layout` / `sphinx-autodoc-api-style`
/ `sphinx-doclang` set. Versioning-directive audit (Spec B).

## Verification

- `docs/` builds clean under the existing strict posture (no new warnings).
- Every new `:option:`/`:confval:`/`:envvar:` role resolves.
- `commands.rst` lists all subcommands with options/args/envvars.
- `coverage` report clean (or gate documents the gaps).
- `sphinx-tippy` hover-previews resolve for the new targets.
